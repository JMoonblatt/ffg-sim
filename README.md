# Fork-First Governance (FFG)

Fork-First Governance is a lightweight governance pattern for collaborative projects.

It is designed to:
- reduce maintainer burnout
- avoid single-point-of-failure leadership
- handle real disagreement without social escalation
- preserve throughput under stress

It does **not** require consensus, moral alignment, or permanent leaders.

---

## Core idea

When disagreement persists, do not argue it out socially.

**Fork the work. Run parallel experiments. Merge based on results.**

Authority is procedural and temporary, not personal.

---

## What this repo provides

- A minimal governance template (`/governance`)
- A simulation showing why these constraints exist (`/sim`)
- No ideology, manifesto, or required belief system

You can use the governance files as-is, modify them, or ignore them entirely.

---

## When FFG is useful

FFG is a good fit when:
- one or two people are quietly becoming bottlenecks
- maintainers are burning out
- disagreements stall progress
- decisions keep reverting to the same person

FFG is **not** optimized for:
- very small projects (1–2 people)
- projects requiring strict hierarchy
- environments where experimentation is impossible

---

## How it works (high level)

- Decisions that affect others are logged
- Stewardship rotates on a fixed schedule
- Disagreements become parallel experiments
- Forks have a time limit and a merge rule
- No role is permanent

See `/governance` for the exact rules.

---

## Status

This is an experiment.

If it fails in practice, that is useful information.
If it works partially, that is also useful information.

There is no claim that this is universally optimal.
